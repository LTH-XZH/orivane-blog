普通文章用 `.md` 就够了。但如果某一篇需要在正文中间插一个组件——一个可以点击的按钮、一张会动的图、一段能交互的表格——那就把后缀改成 `.mdx`。

`.md` 和 `.mdx` 在同一个目录里混着放，路由规则完全一样，不用改任何配置。

## 它能做什么

MDX 是 Markdown 的超集，允许在正文里写 JSX：

```mdx
import HeaderLink from '../../components/HeaderLink.astro';

<HeaderLink href="/about/">点我</HeaderLink>
```

导入的组件和普通 Astro 组件没有任何区别，可以传 props、可以用 slot。

## 试着点一下

下面这个按钮就是 MDX 里嵌进去的组件：

import HeaderLink from '../../components/HeaderLink.astro';

<HeaderLink href="/about/" onclick="alert('这是 MDX 里的组件，点了会弹这个框。')">
	嵌入的组件 · 点我
</HeaderLink>

## 什么时候别用

**能写成纯 Markdown 的，就别用 MDX。** 一旦引入组件，文章就带上了代码依赖：组件改了、删了，旧文章会跟着坏。纯文本活得最久。
