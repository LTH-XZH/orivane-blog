# 改内容的方法

所有文字都在源码里，改完 → `npm run build` → 上传 `dist/` 就生效。

---

## 一、首页那几块文字在哪

文件：`src/pages/index.astro`

打开会看到五个区块，从上到下：

```astro
<section class="home-hero">
	<div class="home-signature">
		<p class="kicker">个人博客 · 自 2026</p>        ← 签名上方那行小字
		<Signature size="xl" loop />                    ← 手写签名（默认 Orivane）
		<p class="home-note">关于工程、阅读与生活。…</p>  ← 签名下方说明
	</div>

	<aside class="motto">
		<p class="motto-label">座右铭</p>
		<h1>把复杂的东西，<br />写得让人愿意读完。</h1>   ← 座右铭正文
		<p class="motto-cite">写完自己愿意再读一遍</p>     ← 座右铭下方那行小字
	</aside>
</section>
```

改法：

| 想改什么 | 改哪一行 |
| :-- | :-- |
| 座右铭 | `<h1>` 里那句，`<br />` 是强制换行，可以删 |
| 座右铭下方小字 | `<p class="motto-cite">` |
| 签名上方的说明 | `<p class="kicker">` |
| 签名下方的说明 | `<p class="home-note">` |
| 签名文字本身 | 给组件加参数：`<Signature text="你的名字" size="xl" loop />` |
| 不想要循环动画 | 删掉 `loop` |
| 底部的「最近更新」列表 | 标题在 `<h2 id="recent-title">`，条数在上方代码里 `posts.slice(0, 6)` 的 `6` |

## 三、写一篇新文章

**1. 在 `src/content/blog/` 新建一个 `.md` 文件**，文件名就是网址：

```
src/content/blog/my-first-note.md   →   /blog/my-first-note/
```

> 文件名用**英文小写 + 短横线**（`chinese-typography`、`reading-2026`）。
> 用中文做文件名也能跑，但网址会变成一串 `%E4%B8%AD…`，又长又难分享。

**2. 开头必须有这一段（frontmatter）**：

```yaml
---
title: '文章标题'
description: '一句话摘要，会出现在列表和搜索结果里。'
pubDate: '2026-11-22'
category: '随笔'
tags: ['读书', '生活']
---
```

- `pubDate` 必须是 `年-月-日` 这种格式，**别写 `11月22日`**，解析不了
- `category` 可以省略（默认「未分类」）
- `tags` 可以省略（默认空）

**3. 正文直接写 Markdown**：

```markdown
正文段落之间空一行。

## 一级分节（前面会自动带一条强调色短线）

### 次级标题

> 引用
```

**4. 想先藏着不发**：加一行 `draft: true`，它只在你本地 `npm run dev` 时出现，正式构建不会生成页面。

## 四、加一个新的文章类别

**不用改代码，也不用建文件。** 类别就是 `category` 这个字段的值：

```yaml
category: '影评'
```

- 第一篇写 `影评` 的文章一出现，`/categories/影评/` 这个页面就自动有了
- 总览页 `/categories/` 会自动按篇数排序
- 导航里的「分类」一直指向总览页，不用动

也就是说，你能用的类别没有上限，随便起名：随笔、读书、影评、摄影、折腾、面试……

如果想给类别加一段说明文字，告诉我，我给它加个字段。

## 五、文章里放图片

有两种放法，区别是**要不要 Astro 帮你优化**。

### 放法 A：`public/images/`（简单直白）

1. 图片丢进 `public/images/`
2. 正文里写：

```markdown
![图片说明](/images/stm32-board.png)
```

路径以 `/` 开头，代表站点根目录。构建时**原样拷贝**，不做任何处理。

- ✅ 路径短、一眼看懂、不会因文章移动而失效
- ✅ 适合：图标、PDF/压缩包等非图片附件、需要固定 URL 的东西
- ❌ 读者下载的就是原图，多大就是多大

### 放法 B：`src/assets/`（构建时自动优化）

1. 图片丢进 `src/assets/images/`
2. 正文里写**相对路径**——相对于这篇 Markdown 文件所在的位置：

```markdown
![图片说明](../../assets/images/stm32-board.png)
```

`src/content/blog/` 往上两级是 `src/`，所以是 `../../assets/images/`。

构建时 Astro 会自动：

- 转成 **WebP**（体积通常只剩 20–40%）
- 按需缩放
- 输出带哈希的文件名，顺便永久缓存

实测：仓库里那张 21 KB 的占位图，构建后输出的 WebP 是 14 KB。

- ✅ 适合：照片、界面截图、任何想省流量的大图
- ❌ 原图仍然躺在仓库里，**磁盘占用一点没少**
- ❌ 路径长，文章挪位置要跟着改

### 怎么选

| 图是什么 | 用哪种 |
| :-- | :-- |
| 截图、照片（几十上百 KB） | **B**，让 Astro 压成 WebP |
| 小图标、SVG、PDF/zip 附件 | **A**，简单直接 |
| 图很多、想统一管理 | **A**，都在一个目录里 |

麻烦一点但效果最好的是 **B**：仓库里存原图，读者拿到的是压缩版。

### 提交前先压一下

不管放 A 还是 B，**原图和它的每一次修改都会永久留在 `.git` 里**，删掉文件也不会让历史变小。所以习惯是：放进仓库之前先压。

```powershell
pip install pillow        # 只需装一次
python scripts/optimize-images.py --dry-run   # 先看会压多少
python scripts/optimize-images.py             # 真的压
```

默认扫 `public/images`，也可以指定目录：

```powershell
python scripts/optimize-images.py src/assets/images
```

规则：最大宽度 1600px、JPEG 质量 82、PNG 开优化，已经够小的自动跳过。

> 不想装 Python 包也行：把图拖进 <https://squoosh.app> 手动压，目标 **宽度 ≤1600、单张 ≤300KB**。

### 格式怎么选

| 内容 | 用什么 |
| :-- | :-- |
| 代码截图、带字的界面图 | PNG 或 WebP（JPEG 会让字发虚） |
| 照片、渐变色块 | JPG 或 WebP（PNG 会到 3–8 MB） |
| 需要透明 | PNG 或 WebP |
| 动图 | WebP（GIF 太大） |

文件名用**英文或拼音 + 短横线**，别用空格和中文：`stm32-board.png` 比 `STM32最小系统.png` 好——后者在地址里会变成一长串 `%E6%9C%80%E5%B0%8F...`。

### 什么时候该把图搬走

| 仓库体积 | 建议 |
| :-- | :-- |
| < 200 MB | 现在这样就够，压一压就行 |
| 200–500 MB | 考虑把图片放 **Cloudflare R2**（免费 10GB、不收流量费），仓库里只留 `img.orivane.me/xxx.jpg` 这样的地址 |
| > 1 GB | 一定要搬，否则每次 clone 都很慢 |

搬 R2 之后，Markdown 里的写法不变，只是把 `/images/xxx.jpg` 换成完整地址。需要的话跟我说，我帮你配 bucket 和自定义域名。

**不建议**：Git LFS（Cloudflare 构建时拉取容易出问题）、随便找的免费图床（会挂、会跑路、还可能限流）。

## 六、改完怎么上线

```powershell
git add -A
git commit -m "新文章：标题"
git push
```

推完 Cloudflare 自动构建，1–2 分钟后线上更新。**不再需要本地 `npm run build`，也不用上传 `dist`。**

本地预览不用 build，`npm run dev` 边写边看就行，`localhost:4321` 会自动刷新。

## 七、常见错误

| 现象 | 原因 |
| :-- | :-- |
| 文章没出现 | `draft: true` 没删；或文件名后缀不是 `.md`/`.mdx` |
| 构建报错 `pubDate` | 日期写成了 `2026/11/22` 或 `11月22日`，要 `2026-11-22` |
| 标题里有英文单引号 | YAML 用单引号包裹时，内部的 `'` 要写成两个 `''`，或者整段用双引号 |
| 图片不显示 | 路径没以 `/` 开头，或图片没放进 `public/` |
| 改完线上没变 | 忘了重新 `npm run build` + 上传 `dist` |
| 中文排版变回黑体 | 霞鹜文楷的 CDN 没加载出来，刷新或换网络重试 |
