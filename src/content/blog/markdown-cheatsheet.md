写文章只用 Markdown。这篇是给自己留的速查表：左边怎么写、右边长什么样，忘了随时回来翻。

想验证某个写法，直接复制到任意一篇草稿里，`npm run dev` 就能看到效果。

## frontmatter

每篇开头必须有这一段，用 `---` 包起来：

```yaml
---
title: '文章标题'
description: '一句话摘要，出现在列表和搜索结果里'
pubDate: '2026-11-28'
category: '技术'
tags: ['Markdown', '写作']
---
```

| 字段 | 必填 | 说明 |
| :-- | :-- | :-- |
| `title` | 是 | 文章标题 |
| `description` | 是 | 摘要，列表里显示 |
| `pubDate` | 是 | `2026-11-28`，必须这个格式 |
| `category` | 否 | 一个分类，写新词就自动开新分类页 |
| `tags` | 否 | 多个标签，只做展示 |
| `draft` | 否 | `true` 时只在本地可见 |
| `updatedDate` | 否 | 更新日期，会显示在日期下面 |

## 标题

```markdown
## 一级分节
### 二级小节
#### 更小的标题
```

`##` 到 `####` 是正文里用的层级，`#` 留给文章标题（由 frontmatter 决定），别再手写。

`##` 会自动在左侧带一条强调色短线，并且自动进右侧目录；`###` 会缩进一级进目录。

## 段落与换行

段落之间**空一行**。只换行不空行，浏览器会把它们连成一段：

```markdown
这是第一段
这是同一段的第二行

这是第二段。
```

想在一段内部强制换行，行尾加两个空格（不好看出来，不推荐），或者用 `<br />`。

## 强调

```markdown
**加粗**
*倾斜*
~~删除线~~
`行内代码`
```

渲染出来：**加粗**、*倾斜*、~~删除线~~、`行内代码`。

中文里 `**` 要紧贴文字，别写成 `** 加粗 **`，否则可能不生效。

## 链接

行内链接：

```markdown
[显示的文字](https://example.com)
[站内文章](/blog/hello/)
[带标题的链接](https://example.com "鼠标悬停时显示")
```

[显示的文字](https://example.com)、[站内文章](/blog/hello/)、[带标题的链接](https://example.com "鼠标悬停时显示")。鼠标悬停在最后一个上，能看到“鼠标悬停时显示”。

自动链接（直接写网址，GFM 会自动转）：

```markdown
https://orivane.me
```

https://orivane.me

锚点跳到本文某一节：把标题文字当作 id 用（中文标题也能用）。

```markdown
[跳到表格那一节](#表格)
```

[跳到表格那一节](#表格)

参考式链接，适合同一地址用很多次：

```markdown
[Astro 文档][astro]

```

[Astro 文档][astro]

[astro]: https://docs.astro.build

## 图片

两种放法，区别在**要不要构建时压缩**：

```markdown
<!-- 放 public/images/：原样输出，路径短 -->
![说明](/images/stm32-board.png)

<!-- 放 src/assets/images/：构建时转 WebP -->
![说明](../../assets/images/stm32-board.png)
```

- 截图、照片 → 放 `src/assets/images/`，会被压成 WebP，读者少下载一半
- 图标、PDF、zip → 放 `public/`，路径短
- 文件名用英文加短横线，别用空格和中文

渲染出来就是一张普通图片：

![STM32 最小系统板](/images/stm32_minimal_system.png)

想给图片加说明文字，用 `<figure>`：

```html
<figure>
	<img src="/images/stm32_minimal_system.png" alt="STM32 最小系统" />
	<figcaption>STM32 最小系统板</figcaption>
</figure>
```

<figure>
	<img src="/images/stm32_minimal_system.png" alt="STM32 最小系统" />
	<figcaption>STM32 最小系统板 · 说明文字会自动用等宽小字排在图片下方</figcaption>
</figure>

## 代码

行内代码用反引号：`const a = 1`。

代码块用三个反引号，后面写语言名就会高亮：

````markdown
```js
const greeting = 'hello';
console.log(greeting);
```
````

支持的常见语言：`js` `ts` `html` `css` `json` `bash` `python` `yaml` `markdown` `diff`。

要在代码块里**再显示一个代码块**，外层就用四个反引号（上面那段就是这么写的）。

## 表格

```markdown
| 左对齐 | 居中 | 右对齐 |
| :-- | :--: | --: |
| 内容 | 内容 | 123 |
| 更长的内容 | 短 | 4 |
```

| 左对齐 | 居中 | 右对齐 |
| :-- | :--: | --: |
| 内容 | 内容 | 123 |
| 更长的内容 | 短 | 4 |

第二行那条 `| :-- | :--: | --: |` 决定对齐方式：左边冒号左对齐、两边冒号居中、右边冒号右对齐。

表格里的竖线要转义成 `\|`，不然会被当成分列。

## 分隔线

```markdown
---
```

单独一行三个减号，渲染成一条细横线。注意和 frontmatter 的分隔符区分——正文里的 `---` 上下都要空行，否则可能被当成标题语法（`文字` 下一行写 `---` 会变成二级标题）。

## 转义

想显示 Markdown 的符号本身，前面加反斜杠：

```markdown
\*不是斜体\*
\# 不是标题
\[不是链接\]
```

\*不是斜体\*
\# 不是标题
\[不是链接\]

可转义的符号：`\` `` ` `` `*` `_` `{}` `[]` `()` `#` `+` `-` `.` `!` `|`

## 脚注

```markdown
这句话需要一个注脚[^1]。

[^1]: 注脚的内容写在文章任意位置。
```

这句话需要一个注脚[^1]。

[^1]: 注脚会自动收在文章末尾，按顺序编号。

## 内联 HTML

Markdown 里可以直接写 HTML，这个站常用的几个：

| 写法 | 效果 |
| :-- | :-- |
| `<kbd>Ctrl</kbd>` | 键盘按键样式：<kbd>Ctrl</kbd> |
| `<mark>重点</mark>` | 荧光笔：<mark>重点</mark> |
| `H<sub>2</sub>O` | 下标：H<sub>2</sub>O |
| `x<sup>2</sup>` | 上标：x<sup>2</sup> |
| `<abbr title="Cascading Style Sheets">CSS</abbr>` | 缩略语，悬停显示全称：<abbr title="Cascading Style Sheets">CSS</abbr> |
| `<p class="note">…</p>` | 段末小字注，虚线上方、灰色 <sup>见下</sup> |

`<p class="note">` 是这个站自己加的样式，适合放“说明”“补充”这类旁注：

```html
<p class="note">这一条是补充说明，字号更小、颜色更浅。</p>
```

<p class="note">这一条是补充说明，字号更小、颜色更浅。</p>

折叠块：

```html
<details>
	<summary>点开看更多</summary>
	里面可以有任意内容。
</details>
```

<details>
	<summary>点开看更多</summary>
	里面可以有任意内容。
</details>

## 数学公式

行内公式用单个 `$`，独立公式用两个：

```markdown
质能方程 $E = mc^2$。

$$
\int_0^1 x^2 \, dx = \frac{1}{3}
$$
```

质能方程 $E = mc^2$。

$$
\int_0^1 x^2 \, dx = \frac{1}{3}
$$

有公式的文章会自动加载 KaTeX，没有公式的文章一个字节都不多下载。写“价格 $5”时如果后面还有第二个 `$`，会被误判成公式，用 `\$` 转义。

## 写完检查一遍

1. frontmatter 的 `pubDate` 是 `年-月-日` 吗
2. 图片放对位置了吗（`src/assets` 还是 `public`）
3. 有没有多余的 HTML 标签没闭合
4. `npm run dev` 里通读一遍，重点看列表和表格有没有错位
5. `git add -A && git commit -m "新文章：xxx" && git push`
