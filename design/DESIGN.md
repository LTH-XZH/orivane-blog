# Orivane Blog · 设计规范 v0.1

> 定位：**编辑式个人博客**——强排版、低噪音、为中文长文优化。
> 视觉样张：`design/preview.html`（浏览器直接打开，右上角 ◐ 切深浅色）

---

## 0. 三条原则

1. **内容优先**：任何装饰都不能抢文字的注意力。页面里最"亮"的元素应该是标题和正文。
2. **只有一个强调色**：全站只有 porcelain 红 `--accent` 一种色彩情绪，其余全是中性色。颜色越少，设计感越强。
3. **用排版制造设计感**：字重、字距、留白、1px 细线——而不是阴影、圆角、渐变、玻璃。这既是审美选择，也是性能选择。

---

## 1. 排版参数（核心，先定这几个数）

| 项 | 值 | 依据 |
|---|---|---|
| 正文字号 | `17px`（移动端 `16px`） | 中文 16px 偏小，17px 是长文舒适下限 |
| 正文行高 | `1.85` | 汉字字面率高，1.5–1.6 会显闷 |
| 阅读宽 | `36em`（≈612px，约 36 个汉字） | 30–40 字/行是中文长文的经验区间 |
| 段间距 | `1.1em`，**首行不缩进** | 屏幕用段距分节；缩进是纸质习惯 |
| 正文字距 | `+0.01em` | 小字号中文轻微放开更清晰 |
| 标题字距 | `-0.02em` | 大字号中文收紧才不散 |
| 字重 | 正文 400 / 标题 600 | 两档足够，别用 300 做正文 |
| 数字 | `font-variant-numeric: tabular-nums` | 列表日期、表格数字才能对齐 |

字号阶梯：`1rem → 1.0625 → 1.25 → 1.45 → clamp(2rem,5vw,2.9rem)`。
**不引入 webfont**。中文 webfont 动辄 2–5MB，收益远小于代价；系统字体（微软雅黑 / 苹方 / 思源黑体）在正文场景已经足够。若后期确实要衬线标题，只自托管**子集化**的思源宋体（常用 3500 字 ≈ 300KB woff2），`font-display: swap` + 预加载，且只用于标题与引用。

## 2. 颜色令牌

| Token | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `--bg` | `#fbf9f6` | `#141312` | 页面底色（暖白"纸感"，不用纯白） |
| `--surface` | `#f4f0e9` | `#1c1a18` | 代码块、行内代码底 |
| `--fg` | `#1b1917` | `#e9e4db` | 正文（不用纯黑，减少眩光） |
| `--muted` | `#6f6862` | `#9a938a` | 日期、摘要、辅助信息（**不用于正文**） |
| `--line` | `#e3ddd2` | `#2a2724` | 1px 分隔线 |
| `--accent` | `#a8442a` | `#e08163` | 链接 hover、标题短线、引用边框、选中态 |

规则：正文对比度 ≥ 7:1（AAA）；`--muted` 只用于 ≥13px 的辅助文字，且对比度 ≥ 4.5:1。
暗色不是简单反色——背景抬到 `#141312`、正文压到 `#e9e4db`，避免纯黑纯白的高对比疲劳。

## 3. 布局

```
┌──────────────────────────────────────────┐
│ nav 64px  sticky · 底部 1px · 品牌字距 .18em │
├──────────────────────────────────────────┤
│ hero：kicker(mono) / h1(≤20ch) / lead     │
│       上下留白 clamp(4rem,10vw,7rem)      │
├──────────────────────────────────────────┤
│ 列表头：小号大写 + 下边框(1px fg)          │
│ 01 ─ 标题 + 摘要 ────────────── 日期(mono) │
│ ──────────────────────────── 1px line    │
│ 02 ─ …                                    │
├──────────────────────────────────────────┤
│ 文章页：meta(日期·时长·标签) → h2 → 正文    │
│         正文列 36em，左对齐，不居中卡片化    │
├──────────────────────────────────────────┤
│ footer：mono 小字 + 上边框                 │
└──────────────────────────────────────────┘
```

- 全站容器 `68rem`，正文列 `36em`——**两级宽度**是形成"版面张力"的关键，别让正文也跟着撑满。
- 首页 = 3 行 Hero + 编号列表，**不做卡片网格**。编号（01/02…）是最便宜的设计感来源。
- 文章页不放大圆角容器，直接铺在页面上；标题下用 2px accent 短线做分节符号。
- 宽屏 >1100px 可加右侧 sticky TOC（`position: sticky; top: 5rem`），窄屏折叠进正文顶部。

## 4. 组件清单与优先级

**P0（第一版必须有）**
`BaseLayout`（head/meta/字体栈/主题初始化）、`Nav`、`PostList`、`PostHeader`、`Prose` 排版、`Footer`、主题切换按钮

**P1（第一周补）**
TOC、上一篇/下一篇、标签页、分页、404、RSS、sitemap

**P2（看需要）**
Pagefind 搜索、动态 OG 图、阅读进度条、代码块复制、图片灯箱

---

## 5. 明确不做（反模式清单）

- ❌ 渐变紫 / 霓虹色 / 双强调色
- ❌ 毛玻璃卡片、8px 以上大圆角、悬浮阴影
- ❌ 粒子背景、滚动视差、进入动画、打字机效果
- ❌ 正文用纯黑 `#000` / 纯白 `#fff`
- ❌ 自动播放、超过 150ms 的 hover 过渡
- ❌ 中文正文 webfont 全家桶

这些不是"不好看"，是**每一条都在消耗阅读注意力**。

---

## 6. 落地到 Astro 的顺序

1. `src/styles/global.css`：把第 1、2 节的表**逐条写成 CSS 变量 + `.prose` 规则**（样张里的 `<style>` 可直接搬）。
2. `src/layouts/BaseLayout.astro`：`<head>` 元信息、字体栈、**防闪白的主题初始化内联脚本**（必须在 `<style>` 之前执行）。
3. `src/pages/index.astro`：Hero + 列表，数据来自 `getCollection('blog')`。
4. `src/pages/blog/[...slug].astro` + `BlogPost.astro`：文章页。
5. `src/content.config.ts`：字段先定死 `title / description / pubDate / tags / draft`——**这一步决定你以后换不换得了皮肤**。
6. 最后才做 TOC / 搜索 / OG 图。

> 关键顺序逻辑：**先用 3 篇文章把 P0 跑通，再谈美化**。设计规范的价值在于"你写 CSS 时不用现场做决定"。

## 7. 验收清单

- [ ] 320 / 768 / 1440 三档无横向滚动
- [ ] 亮暗两套：正文对比度 ≥ 7:1
- [ ] 键盘 Tab 全站可达，`:focus-visible` 可见
- [ ] `prefers-reduced-motion` 下无动画
- [ ] 首屏 JS < 5KB（只有主题切换 + 必要的 island）
- [ ] Lighthouse 性能 / 可访问性 ≥ 95
- [ ] **主观验收**：一段 800 字中文长文，从头读到尾不累——这条最重要，其他都是它的手段
